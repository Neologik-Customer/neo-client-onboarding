# Preparing the TLS Certificate

## Overview

Your Neologik environment is reached over HTTPS at its host name, for example `neologik.contoso.com`. It needs a TLS certificate for that name, issued by a certificate authority your users' devices trust, and supplied as a single password-protected PFX (PKCS#12) file.

This guide explains which files you need, how to combine them into a PFX file with `Export-NeologikCertificate.ps1`, and how to import the PFX file into the environment's Key Vault. The PFX file and its password stay with you: do not send either to Neologik.

If you already hold the certificate as a PFX file that contains the private key and the full chain, go straight to [Import the PFX file into the Key Vault](#import-the-pfx-file-into-the-key-vault).

## The files you need

| File | Usual extension | Where it comes from |
|---|---|---|
| Private key | `.key` | Generated by your organisation with the certificate signing request. It never leaves your control |
| Server certificate | `.crt` or `.cer` | Issued by the certificate authority in response to the request |
| Certificate authority bundle | `.pem`, `.crt` or `.p7b` | Supplied by the certificate authority: its intermediate and root certificates |

The certificate must be issued for the environment's host name, or as a wildcard that covers it.

If you are unsure which files to request, ask your certificate provider or your PKI team for the private key, the server certificate and the full intermediate bundle, in PEM or P7B format.

## Create the PFX file with the script

1. Copy the three files into the `cert` folder of the kit and name them as follows, or keep their names and pass them as parameters:

   | File | Name |
   |---|---|
   | Private key | `private.key` |
   | Server certificate | `server.crt` |
   | Certificate authority bundle | `ca-bundle.pem` |

2. Open PowerShell 7 in the kit folder, allow the script to run in this session, and run it:

   ```powershell
   Unblock-File .\Export-NeologikCertificate.ps1
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
   .\Export-NeologikCertificate.ps1
   ```

   With your own file names:

   ```powershell
   .\Export-NeologikCertificate.ps1 -KeyFile cert\mysite.key -CertFile cert\mysite.crt -BundleFile cert\chain.pem
   ```

3. Enter a password for the PFX file when asked, and enter it again to confirm. The password is not shown as you type.

The script writes `cert\certificate.pfx`, checks that the file opens with the password and reports the number of certificates in it. It warns when the file holds fewer than two certificates, which means the chain is incomplete.

**A bundle in P7B format.** Pass the file with `-BundleFile`. The script converts it and, where it holds more than one certificate, removes the first, which in a P7B file from a certificate authority is the server certificate. If your P7B file holds the certificate authority certificates only, convert it to PEM yourself, as described in [Prepare the files](#2-prepare-the-files), and pass the PEM file.

If OpenSSL is not installed, the script installs it with `winget` and accepts the package and source agreements on your behalf. To install it yourself beforehand, see [Install OpenSSL](#1-install-openssl).

## Import the PFX file into the Key Vault

1. In the Azure portal, open the Key Vault named in the completion summary of the onboarding script.
2. Select **Certificates**, then **Generate/Import**.
3. Choose **Import** and enter:

   | Field | Value |
   |---|---|
   | Certificate name | `keyvault-neo-ingress` |
   | Upload certificate file | The `.pfx` file |
   | Password | The password of the PFX file |

4. Select **Create**.

The password is used at import only and is not stored in the Key Vault. Keep the PFX file and its password in your organisation's secure storage, or delete the file once the import has succeeded.

If you cannot import into the Key Vault, the certificate can be supplied through the deployment storage account instead. See [TECHNICAL-REFERENCE.md](TECHNICAL-REFERENCE.md#the-tls-certificate).

## Create the PFX file by hand

Use these steps if you prefer not to run the script, or to investigate a file the script rejects.

### 1. Install OpenSSL

1. Download OpenSSL for Windows from https://slproweb.com/products/Win32OpenSSL.html. The "Win64 OpenSSL Light" edition is sufficient.
2. Run the installer and accept the defaults.
3. Open a new PowerShell window and confirm the installation:

   ```powershell
   openssl version
   ```

### 2. Prepare the files

Copy the three files into the `cert` folder and open PowerShell in that folder.

**A bundle in P7B format.** Convert it to PEM:

```powershell
openssl pkcs7 -print_certs -in ca-bundle.p7b -out ca-bundle.pem
```

Some bundles also contain the server certificate, which must not appear twice in the PFX file. List the certificates in the bundle:

```powershell
openssl pkcs7 -print_certs -in ca-bundle.p7b | Select-String "subject="
```

If the server certificate is listed first, remove it from the converted bundle:

```powershell
$content = Get-Content ca-bundle.pem -Raw
$certs = $content -split '(?=-----BEGIN CERTIFICATE-----)' | Where-Object { $_ -match 'BEGIN CERTIFICATE' }
$certs[1..($certs.Count - 1)] -join '' | Set-Content ca-bundle.pem
```

**A private key file that also holds the signing request.** Extract the key alone:

```powershell
openssl rsa -in private.key -out private-clean.key
```

The file `private-clean.key` holds the private key unencrypted. Delete it when the PFX file has been created.

### 3. Create the PFX file

```powershell
openssl pkcs12 -export -out certificate.pfx `
  -inkey private.key `
  -in server.crt `
  -certfile ca-bundle.pem `
  -keypbe PBE-SHA1-3DES `
  -certpbe PBE-SHA1-3DES `
  -maciter
```

OpenSSL asks for the export password twice. Use `private-clean.key` in place of `private.key` if you extracted the key in the previous step.

The `-keypbe` and `-certpbe` options select algorithms that the Azure Key Vault import accepts. The PFX file is a transport container only: once imported, the certificate and key are stored under the Key Vault's own encryption.

### 4. Check the PFX file

Confirm that the file opens. OpenSSL asks for the password; no further output means the file is valid:

```powershell
openssl pkcs12 -in certificate.pfx -noout
```

List the certificates in the file:

```powershell
openssl pkcs12 -in certificate.pfx -nokeys | Select-String "subject="
```

The list shows the server certificate, followed by each intermediate certificate and, where the bundle includes it, the root certificate.

## Troubleshooting

| Message or symptom | Cause | Action |
|---|---|---|
| The script reports "Not found" for a file | The file is not in the `cert` folder under the expected name | Rename the file, or pass its name as a parameter |
| "Passwords do not match" | The two entries differed | Run the script again |
| "PFX was not created" | The key and the certificate do not belong together, or a file is not in PEM format | Check that the private key is the one generated with the signing request for this certificate |
| The script warns that the chain may be incomplete | The bundle lacks the intermediate certificates | Obtain the full bundle from your certificate provider |
| "Unable to load private key" (by hand) | The key file also holds the signing request | Extract the key, as in step 2 of [Create the PFX file by hand](#create-the-pfx-file-by-hand) |
| The Key Vault import refuses the file | The PFX file was created with other encryption options, or the password is wrong | Create the file again with the script, or with the options shown in step 3 of [Create the PFX file by hand](#create-the-pfx-file-by-hand) |
| The browser reports a certificate error after deployment | The certificate was issued for a different host name, or the chain is incomplete | Check the names on the certificate and the certificates in the PFX file, as in step 4 of [Create the PFX file by hand](#create-the-pfx-file-by-hand) |
